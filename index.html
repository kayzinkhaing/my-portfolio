TMS — Training Management System

TMS (Training Management System) is a centralized platform I developed to help training centers manage courses, instructors, students, attendance, payments, communication, and certification in one professional system — replacing manual processes with automation, accuracy, and real-time reporting.

System Overview

TMS is designed to manage the complete lifecycle of a training program — from course creation and student enrollment to attendance tracking, payments, reporting, and certificate issuance. The system focuses on security, scalability, and clean architecture using best practices.

Core System Modules

  • User & Role Management (RBAC): Admin, Instructor, Editor, Staff, Student with permission control.
  • Course Management: Course setup, fees, duration, instructors, technologies.
  • Class Scheduling: Weekly timetables, auto-generated class dates, conflict checking.
  • Student Enrollment: Registration, course application, approval workflow.
  • Attendance Management: QR-code based attendance with present, late, absent states.
  • Instructor Management: Assigned courses, students, schedules, blog creation.
  • Finance & Payments: Payment tracking, invoices, outstanding balance reports.
  • Notifications: Email & in-app alerts for classes, payments, announcements.
  • Dashboard & Reports: Real-time charts, exports to PDF / Excel.
  • Certificate Management: Auto-generated certificates based on attendance criteria.

Security & Access Control

The system uses Role-Based Access Control (RBAC), policies, middleware, email/password authentication, social login (Google & GitHub), and Two-Factor Authentication (2FA) to protect sensitive actions across the platform.

CQRS Clean Portfolio Architecture

A modern full-stack blogging platform implementing CQRS architecture with advanced separation of read and write operations for optimal performance and scalability. **Built using Vue 3, Laravel, and data synchronization via RabbitMQ.**

Project Purpose

This system is designed to demonstrate a modern, scalable blog application implementing the Command Query Responsibility Segregation (CQRS) pattern. It separates read and write operations to optimize performance, allowing for independent scaling of each component based on demand.

Architecture Overview

The system follows a sophisticated event-driven architecture with clear separation between write and read operations:

  • Write Side (Laravel + MySQL): Handles all commands...
  • Event Bus (RabbitMQ): Serves as the central message broker...
  • Read Side (Laravel Worker + MongoDB): Listens to RabbitMQ queues...
  • GraphQL API (Laravel): Uses Laravel Lighthouse to serve...
  • Frontend (Vue 3 + Apollo Client): Queries GraphQL endpoint...

Data Management

The system maintains two separate data stores optimized for their specific purposes:

  • MySQL: Serves as the authoritative write database...
  • MongoDB: Contains optimized collections for fast queries...
